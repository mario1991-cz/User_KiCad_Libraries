# User KiCad Libraries

Personal KiCad 10 libraries (symbols, footprints, 3D models, SPICE models, design blocks).
Kept outside projects; all library-table entries use the path variable `${USER_LIB_DIR}`,
so the folder can be moved by changing that one variable. Kept in a Git repository (GitHub).

## Layout
| Folder | Content | Naming |
|---|---|---|
| `symbols/` | `.kicad_sym` libraries | `User_<Category>.kicad_sym` |
| `footprints/` | `.pretty` libraries | `User_<Category>.pretty` |
| `3dmodels/` | `.3dshapes` folders, STEP only | `User_<Category>.3dshapes` (same category as the footprint library) |
| `spice/` | SPICE models (`.lib`, `.mod`, `.sub`) | manufacturer or part family name |
| `design_blocks/` | `.kicad_blocks` libraries | `User_<Category>.kicad_blocks` |

Categories follow the official KiCad library names (`Regulator_Switching`, `Amplifier_Operational`,
`Connector`, `74xx`, ...). A library is created when its first part is added, never empty.

## Rules
- Use an official KiCad symbol/footprint whenever one exists. Add a part here only if KiCad lacks it
  or it needs a deliberate deviation.
- Prefer KiCad's official footprints in own symbols; own footprints only when KiCad has none.
- Symbols follow KiCad KLC style: 2.54 mm pin grid, inputs left, outputs right, power top/bottom,
  IEC (European) graphic conventions.
- Mandatory symbol fields: Reference, Value, Footprint, Datasheet (manufacturer PDF URL),
  Description, Keywords (`ki_keywords`), Footprint filters (`ki_fp_filters`).
- `Sim.*` fields (Sim.Library, Sim.Name, Sim.Device, Sim.Pins) are filled whenever a SPICE model is
  available; `Sim.Library` uses `${USER_LIB_DIR}/spice/<file>`. Models need ngspice with XSPICE
  (KiCad's ngspice has it).
- Models whose licence forbids redistribution (e.g. Central Semiconductor 2N5551) are not stored here:
  the symbol uses `Sim.Library = ${KIPRJMOD}/spice/<file>` and each project keeps its own copy of the model.
- Every new model is checked in ngspice before it is linked; LTspice-only syntax (`mfg=`, `Vceo=`, `Icrating=`,
  Diotec-style parametrised subcircuits) makes ngspice abort.
- No Manufacturer / MPN fields; vendor/SnapEDA extra fields (MF, MP, Price, Availability, PARTREV, ...) are removed.
- Names of own parts stay short and readable (original vendor names), KiCad naming conventions are not enforced.
- Connector pins are `passive` (power source pins only on real sources such as regulator/converter outputs).
- References in designs always end with a number (KiCad refuses to simulate `Rz` etc.).
- All texts, names and comments in English.

## User_74xx_CSN and User_4xxx_CSN – unofficial, obsolete symbol style
> **Warning:** `User_74xx_CSN` and `User_4xxx_CSN` are **unofficial** libraries. Its symbols follow the classic Czechoslovak
> ČSN drawing style known from TESLA catalogues. That standard is **withdrawn** and has been replaced by
> ČSN EN 60617-12 (IEC 60617-12). The library is kept for hobby and retro (TESLA) projects only; do not use it
> where conformity with current standards is required.
- Simple gates look the same in both standards (rectangle with `&`, `≥1`, `1`, `=1`, negation circle).
- Flip-flops, counters, decoders etc. are drawn in the classic style (TESLA catalogue), not with IEC dependency notation.
- One unit per gate/element plus a separate power unit (VCC/GND); Footprint field left empty, footprint filters for DIP/SOIC/TSSOP.
- Keywords contain the TESLA equivalent (e.g. `MH7400`) for searching.
- Layout of complex parts: three columns (input labels | function abbreviation | output labels); groups separated by
  lines, group headers such as `&G`, `&L`, `A`, `Z` (3-state outputs). Abbreviations as in TESLA catalogues:
  `T` flip-flop, `TE` edge register, `TL`/`RGL` latch, `RG8` shift register, `CT2`/`CT10` counter,
  `B/D`, `B/DEC`, `DC`, `X/Y` decoders, `MUX`/`MX` multiplexer, `SM` adder.
- Clock inputs: filled arrow. Tip at the body = rising edge (`C_H`); tip pointing away from the body
  towards the pin = falling edge (`C_L`, e.g. 74112). Negation = circle.
- Parts without a TESLA catalogue drawing (e.g. 74161, 74163, 74191, 74165, 74595) are drawn from their function in the same style.
- Generated by local scripts (not in the repository).
- 4000 series: supply pins VDD/VSS (4051/4052/4053 also VEE in the power unit); analog switch/multiplexer channels are `passive` pins; keywords contain the TESLA name (e.g. `MHB4011`).

## Design blocks
- A block contains only footprints, tracks and vias (plus the schematic). **No zones/copper pours and no Edge.Cuts outline**:
  pours are a board-level decision and the target board's planes connect the nets.
- Every GND pad gets its own short trace + via, so GND connects to the target board's plane on any layer
  (a 2-layer target without any GND pour would show these vias as unconnected in DRC).
- Pours and a temporary outline may be used in the block's work project only, to verify connectivity with DRC.
- A block has no required shape; in KiCad it is just a group.
- Usage in the PCB editor: **place the design block first, then run "Update PCB from Schematic"**.
  Updating first brings the block's parts in as loose footprints without the layout.
- Placed blocks are not updated when the library block changes.

## Tools
Helper scripts (3D model generators, symbol generators, mechanical drawing) are kept locally in `tools/`
and are deliberately **not part of this repository** (`.gitignore`). Models and symbols made with them are
ordinary KiCad/STEP files and need no script.

## Candidates (add when needed)
- 4000 series: 4020, 4024 (binary counters), 4026, 4033 (decade counter + 7-segment decoder), 4510, 4516 (up/down counters),
  4514, 4515 (1-of-16 decoder with latch), 4067 (16-channel analog mux), 4099 (8-bit addressable latch; TESLA drawing exists),
  4042 (quad D latch), 4543 (BCD to 7-segment LCD decoder), 4098 (dual monostable).
- 74HC40xx parts (74HC4051/4052/4053/4060/4040/4017 …) are pin-compatible with the 4000 originals: use the User_4xxx_CSN
  symbol and change Value (mind the 2–6 V supply range of HC).

## Heatsinks and DRC
A heatsink is a separate part (HS*) placed over its transistor or regulator, so the courtyards overlap and the mounting hole lies inside the heatsink courtyard. The project templates (JLC_2L, JLC_4L, TSM_2L) contain a custom rule `Heatsink courtyard` that ignores exactly these two checks between HS* and Q*/U*/D*; any other part overlapping a heatsink is still reported. For older projects copy the rule into the project's `.kicad_dru`.

The former combined footprint `User_Heatsink:TO-220-3_Horizontal_V4330N` (transistor + heatsink in one) was moved into the H-bridge project library (2026-11-08) and is no longer part of this library.
